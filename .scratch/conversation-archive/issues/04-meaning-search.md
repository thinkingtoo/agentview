# 04: Meaning search with gemma on the tailnet

**What to build:** searches also find conversations by meaning ("the session where the chime did not ring" finds one that never used the word chime). Meaning hits are merged into the same result list as keyword hits. If the embedder cannot be reached, keyword results still come back, and the page says meaning search is off. Spec: `docs/specs/2026-09-29-conversation-archive.md` (decisions table and measured facts).

**Blocked by:** 02: Keyword search across all interactive conversations

**Status:** resolved

- [x] The embedder is the EmbeddingGemma-300m int4 service (768 dimensions), not the bge-m3 one. Its URL and API key come from a local config file with mode 600 and never go in this repo, which is public.
- [x] Stored passages go through the embedder's **document** endpoint (batch, at most 100 texts per call) and queries through its **query** endpoint. A test confirms each path calls the endpoint it should.
- [x] Vectors are stored in the same SQLite file along with the model identity from the embedder's model endpoint. When that identity changes, every vector is rebuilt; vectors from two models are never mixed.
- [x] Ranking merges the keyword and meaning lists, for example with reciprocal rank fusion, and results are still grouped by conversation.
- [x] With the embedder down, a search returns keyword results within the usual time and flags meaning search as off. Tested by pointing at an unreachable URL.
- [x] The backfill embeds all interactive conversations and reports its duration. A search on a paraphrase of a known conversation finds it: record the query and the result in the ticket's closing note.

## Comments

**Closing note (Birgit, 2026-09-29).** Built on `feat/04-meaning-search`. The code is `embedder.py` (new: the client and the local config), `archive.py` (vectors, the embedding step in `update`, `find`), the `/api/search` route in `server.py`, a notice and a tag in `index.html`, and `tests/test_meaning.py`. Schema 4: the first run after this lands rebuilds the index, then embeds it. The real query, its results and the curl output are in `~/.claude/pm/evidence/04.md`, outside the repo, because they carry real conversation titles.

1. **EmbeddingGemma, config outside the repo.** `embedder.Embedder.identity()` accepts one model by its exact reported name at 768 dimensions with both prompts named, and refuses anything else, the bge-m3 service included (`Guard`, run against the real constants). The address and key are read from a local file, mode 0600, and a file others can read is refused. The reasons the page and the log get are fixed text: nothing the service says, and nothing about where it is, is repeated.
2. **Document and query endpoints.** `test_stored_passages_go_through_the_document_endpoint`, `test_the_question_goes_through_the_query_endpoint_and_only_that`, `test_a_batch_never_holds_more_than_a_hundred_passages` (250 passages go in batches of 100, 100 and 50), and `test_only_passage_text_is_sent` (no name, title, path or session id in what is sent).
3. **Vectors and identity.** A `vectors` table in the same SQLite file, dropped with its passage by a trigger, and the identity from the model endpoint in `meta`. A different identity drops every vector and embeds again (`test_a_different_model_rebuilds_every_vector_and_never_mixes`). The identity is asked afresh for every query and every batch, before and after: a query made while the model changed is not used, a batch made while it changed is not stored (`Freshness`).
4. **Merged, grouped.** Reciprocal rank fusion over the keyword list and the meaning list, one row per conversation, a conversation found both ways outranking one found either way (`test_the_two_lists_are_merged_one_row_per_conversation`). A passage counts from a cosine of 0.35: on the real index, eight unrelated queries put their best passage at 0.37 or lower and five real ones at 0.43 or higher. A row found by meaning alone is tagged *by meaning*.
5. **Embedder down.** Unreachable, silent, not ready, misconfigured, the wrong model, another model than the vectors came from, a mistyped URL, or vectors that are not finite numbers: the keyword hits come back and the answer says `meaning: off` with a reason (`EmbedderOff`, and `Route` through the real HTTP route). Live, with the embedder config pointed at a non-routable address: 11 keyword hits and the flag, in 0.68 s for the first search (the connect timeout) and 0.017 s for the next, against 2 ms for a keyword-only search. The embedder is then left alone for 30 s.
6. **Backfill, and a paraphrase.** From an empty scratch index built from the real transcripts: 541 conversations, 7,665 passages, 128.14 s in all, 106 s of it embedding, 75 MB, mode 0600. A search on a paraphrase that shares no content word with a known conversation found it as result 2 of 30, among other conversations about the same event; the query and the result are in the private evidence. Hybrid search takes 116 to 150 ms in the library and about 0.3 s over HTTP the first time.

**Not tested on the live server.** It runs the code from before this ticket, and restarting it kills the sessions in its cgroup (ticket 06). Every check above ran on a second server from the worktree, on another port, with its own log directory and a scratch index; the live index and its timer were not touched. The merge makes the timer's next run rebuild the live index to schema 4 and embed it (about two minutes); a search on the old server code in that window can answer "search failed" once.
