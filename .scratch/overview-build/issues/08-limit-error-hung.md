# 08: Limit, Error and Hung

**What to build:** The remaining stuck kinds. Limit: a rate-limit API error is the last record, with the reset time when given and how long it has been held. Error: any other API or auth error as the last record, with its type. Hung: busy, but not moving (by the movement rule) for `hung_after_minutes` (default 10), with the last tool and its age. The card's state follows the full order: Needs you, Error, Hung, Limit, moving, idle. Waiting on jobs and idle are never stuck. Today's `stuck` stays computed for the chime.

**Known limits (ticket 08, accepted by the boss's rulings of 2026-10-19):**
- CPU time under a waited-on command is kept per pid in memory, so a short false-Hung window is possible right after a server restart.
- The teammate detection only sees a teammate while it writes (first seen within 40 minutes), only in-process teammates with no registry row, and only in the folders of the lead's own directories.
- A busy session whose last word ended its turn (a turn end, or an API error as the reply; a compaction does not open it again) reads idle even when the registry says busy: neither moving nor stuck, and idle in the mix.
- A manual `/compact` opens the turn (the plain "/compact" user record comes first, 49 of 52): a lead whose registry stays `busy` would read Hung 10 minutes after it. Not observed: 7 of 7 went idle within a minute.
- A prompt typed while the session is busy is written as an `attachment` of type `queued_command` (`origin.kind` human, 137 in 14 days) that the Error/Limit reader ignores, so the model's reply ends an error, not the typed line. 0 cases after an API error.
- A tool's result that follows a server_error in the middle of a turn that goes on keeps the Error until the model's next reply (2 of 98 errors: ca17ce02 2.2 minutes, 8879da84 0.1 minutes): the ruled outcome of (a).
- A compaction clears the Error and leaves the turn as it is, so a lead that is compacting can read turn-over for a few seconds (f6834ab6, 10 s): the ruled behaviour of hunt 08-3.
- Open, outside 08 and with the boss to rule: the reader cuts a transcript into records with `str.splitlines()`, which also cuts at a raw U+2028, U+2029 or U+0085 inside a JSON string and drops that record (read-only count: 52 of the main transcripts hold one, 140 records are invisible to the reader, 63 of them tool calls).
