# The overview: every project at a glance, and what each session needs

**2026-10-18 · design agreed through the overview map (12 tickets), not implemented**

Today's main page groups sessions by folder and paints one flag per session. It splits one
piece of work across many blocks (7 repositories became 14 groups on 2026-10-17), it cannot
say *why* a session is stuck (today's `stuck` is a false alarm 86% of the time), and it has no
sign of life for a session that is quietly waiting on tests. The person wants one calm view:
every project, what it is about, which sessions are moving, which are stuck and why, and one
click to the session that needs them.

The overview **replaces today's main page**. Search, ⟲ closed and reopen stay as they are.
The decisions behind each section are on the map, `.scratch/overview/map.md`; each section
names its ticket.

## Scope

- This laptop only: interactive Claude Code and Codex sessions, their workers, and Codex
  `exec` runs.
- Out: acting from the page (answering a question or a dialog without jumping), other
  machines, cloud sessions, systemd routines, a phone view, any change to the chime, and
  replacing dialogs with one list of things left for the person.

## Words

`GLOSSARY.md` defines them: Session, Project, Boss, Worker, Track, Context line, Overview,
Stuck, Needs you, Working-on line, Session line, Jump, Finished, Movement.

## 1. Projects

*Tickets: "What signals exist to group sessions into projects?", "How does a session get its
project?"*

A session's project, **first match wins**:

1. **The person's own setting** (`config.json`, `assign`).
2. **The boss track.** A boss's marker `~/.claude/pm/.boss-sessions/<sid>`; for a worker, its
   tmux `boss-<track>` session, then its `reportsTo` boss's marker, then the single tracker
   naming it. When they disagree: for a worker, tmux track, then `reportsTo`, then tracker; for
   a boss, its marker beats its tmux name. A track is **one project across repositories**: a
   worker in another repository sits under its boss's project, and one repository holding
   several tracks becomes several projects.
3. **The repository**, keyed by its remote. Worktrees fold onto their parent repository. Each
   `clients/<client>/` subfolder is its own project. Plain folders holding several repositories,
   and `~/Projects` itself, are never a project.
4. **Today's folder rule.**
5. **A guess** from the paths the session touched. A session placed only by the guess, or by
   nothing, goes to **No project**, the last column, with the guessed project as a one-click
   suggestion ("→ Invoice tool").

For rules 3 and 4 the **launch folder decides**: a session never changes project because it
`cd`s elsewhere. Codex sessions reach only rules 3 to 5.

**By hand**: rename, merge, and move a session, a whole track or a whole repository into a
project. Stored in `config.json` (`assign`, `names`), keyed by track or repository so it holds
for future sessions; moving a single session lasts as long as that session.

**A boss shows once**, at the top of its track's project.

## 2. Project name and context line

*Ticket: "Where does a project's "what is this about" line come from?"*

- **Display name**: the track slug, the repository name (from the remote, so worktrees share
  it), or the client folder name, prettified: hyphens and underscores become spaces, first
  letter capital, the brand stays lowercase. The raw slug in grey on hover. Renames live in
  `config.json` `names`.
- **Context line**, first that exists:
  1. the person's own line, edited in place on the page, stored in `config.json` beside the
     rename and keyed by track or repository;
  2. for a track, the first sentence of `## Outcome` in `~/.claude/pm/<track>.goal.md`;
  3. for a repository, the README's first prose paragraph, then the opening of CLAUDE.md or
     AGENTS.md (headings, badges and `@` includes skipped);
  4. otherwise up to two recent session titles, greyed and marked as a guess, plus a quiet
     "add a line".
  Cut at about 140 characters, full text on hover. No project has no context line.
- **Track status and progress**: the word from `_Status:` as a small tag (OPEN, PAUSED, MET),
  and "N of M" from the ticked boxes under `## Done when` as a small bar, no percentage. MET
  shows "done" whatever the boxes say. Repository projects show no progress.
- **Notes link**: searches the brain on click with the project name plus its context line and
  shows the top 3 hits. The brain is never the source of the context line.

## 3. Layout

*Ticket: "How should the overview look?". Prototype: variant H on the local branch
`prototype/overview-layout`.*

**One column per project**, read top to bottom. Heights change all the time as sessions get
stuck and unstuck; in a column that only pushes down its own project. Track projects first,
No project last. Columns are at least 230 px wide; more than fit scroll sideways.

### Project card (top of each column)

In this order, and **the state is always the second line, never above the name**:

1. the name, with the status tag for a track;
2. the **project state**: its most urgent session decides, in this order: Needs you (amber),
   Error or Hung (red), Limit (purple), moving (green), all idle (grey). Shown as a small word
   (NEEDS YOU, ERROR, HUNG, LIMIT, MOVING, ALL IDLE);
3. the context line, up to three lines;
4. "N of M" for a track, and the notes link;
5. the **project movement strip**: one bar per minute for the last 30 minutes, the sum of the
   writes of every session in the project, and under it "2 moving · 2 stuck · 0 idle".

The card is **always coloured** by the project state: its top edge, a light tint, the state
word and the strip's bars. Finished sessions (section 7) do not count toward it.

### Session tile (under the card, boss first)

- a dot (green and breathing while moving, the kind's colour when stuck, grey when idle), the
  session name, `boss` / `codex` / `exec` tags, the stuck kind as a tag, and the jump on the
  right ("open ↗", "attach ↗", or "no terminal" greyed);
- the **working-on line** (section 4);
- the **movement sign** (section 5);
- when stuck: the reason, and a context box (section 6);
- an unread handover: the last thing the session said, in quotes, until it is seen;
- in No project: the suggestion chip.

Tiles carry **no strip of their own**; the project strip is the only graph. A stuck tile has a
border in its kind's colour.

### Header

The counts are links: "3 need you", "3 other stuck", "5 moving". A click lights up the matching
sessions, fades the rest, and shrinks columns with none to their card. A second click clears
it. Finished sessions are not counted.

### Copy

A **copy** button on commands only: a Bash permission prompt's command, and a command among the
things left for the person. Copying never answers the session; that stays in the pane.

### Banners

Page-wide conditions are one banner across the top, never a per-session kind: a full disk, and
a Codex usage limit ("Codex usage limit reached, resets at 14:20", until the reset time).

## 4. The working-on line

*Ticket: "What does the "working on" line of a session say?"*

The line says what **job** the session is on, never what it is doing this minute. One line,
ellipsis, full text on hover.

- **Source, first that exists**: the person's own line; `did` from the session line; Claude
  Code's `title`.
- **A busy session keeps its last `did`** until it writes a new one, so the tile does not flip
  at every prompt. Only `ask` and `n` stay scoped to their turn, as today, so Needs you stays
  accurate.
- **Nothing at all**: the last prompt, clipped and greyed as a stand-in; with no prompt, the
  branch or folder, greyed.
- **No repeats**: a line equal to the project's name or context line is skipped for the next
  source; with nothing left, the tile has no line.
- What today's second line carried moves out: `doing` into the movement sign, `ask` into the
  Needs you context, `said` into the unread handover only. Today's second line goes away.

## 5. Movement

*Ticket: "What signals show that a session is moving?"*

A session is **moving** when any of these holds:

- its transcript, or one of its subagents' transcripts, was written recently;
- a shell under its process is using CPU;
- it has an open background task (started task ids minus task-notification and `TaskStop`
  ids) with a live shell behind it;
- for a Claude session that started a `codex exec` run: that run is alive (found by walking
  up from the `codex` process to the session's pid).

The peer `status` alone is never evidence: it has no heartbeat. The main process's own CPU only
backs up a stale `busy`.

**The movement sign** on each tile:

| situation | sign |
|---|---|
| writing | "writing · 8s ago" |
| waiting on tests, a subagent, a background job or a Codex run | "waiting on: tests, 12 min" |
| a long tool run | the same shape, replacing today's `tool` flag |
| idle | "idle 14 min", with no kind; it never reads as "your turn" |
| stuck | per kind, section 6 |

**The project strip** counts, per minute, the records written by the project's sessions over
the last 30 minutes. No model or API call is involved: the server already reads every new
transcript line each 3-second poll (`Tailed` in `providers/base.py`); the strip is a 30-slot
counter added to that reading.

## 6. Stuck kinds

*Tickets: "What has stuck looked like on this machine so far?", "Which kinds of stuck does the
overview name, and how is each detected?"*

| kind | detected when | reason shown | context shown |
|---|---|---|---|
| **Needs you** | an open AskUserQuestion, an open permission prompt, or a session line with `n` > 0 (all one level) | "Question", "Permission prompt", or "3 things left for you" | the question with its options; the tool and its command (with copy); the line's `ask`, or the list of things left |
| **Limit** | a `rate_limit` API error is the last transcript record | "Rate limit" | the reset time when the error carries one, and how long it has been held |
| **Error** | any other API or auth error is the last record | the error type (overloaded, auth, server) | the error and when |
| **Hung** | busy, but not moving (section 5) for 10 minutes (`config.json`, like today's `stuck_after_minutes`) | "Not moving for 14 min" | the last tool and how long ago |

Not stuck: waiting on tests, a subagent, a background job or a Codex run (that is movement);
idle (neutral). Error loops, a session off track, and a session waiting on a peer that never
replies are left to the movement sign.

**Today's flags stay.** `stuck`, `waiting`, `ready` and `tool` keep being computed as they are,
because the chime reads them. Only the page shows the kinds. Hung replaces `stuck` on the page;
counting background work as movement removes the 328 subagent and background false alarms.

## 7. Finished sessions

*Ticket: "When is a session finished and forgotten, and how does it show?"*

- **Finished**: idle for 2 hours or more (`config.json`), its handover seen, and nothing left
  for the person (`n` = 0). An unread handover or a thing left for the person keeps a full
  tile however old.
- **A pill** at the foot of its project column: name and idle time on one line, the
  working-on line on hover, a click jumps. Never hidden: over 30 days, 520 idle spells of 2
  hours or more were followed by more work.
- **Not counted** in the project state, its summary line, or the header counts. A project with
  only pills shows ALL IDLE in grey.
- **Back to a tile** on any sign of life (a prompt, a write, a stuck kind), and it shrinks
  again after the next 2 hours idle.
- **Pinned by hand**: a pill can be pinned open as a full tile, for that one session, until
  unpinned or the session closes. Kept in agentview's own state beside the seen marks. A
  pinned idle session counts as an ordinary idle tile.

## 8. The jump

*Ticket: "Where does one click land, for each kind of stuck?"*

- **Every kind lands on the stuck session's own terminal pane**, as `jump.py` does today
  (WezTerm, tmux, Konsole). An open question or permission prompt is drawn in the pane itself.
  With `n` > 1 the list is in the session's last message, at the bottom of the pane.
- **The stuck session itself**, never its boss. A boss relaying a question shows Needs you on
  its own tile.
- **Background sessions** (`claude --bg`): a new WezTerm tab running `claude attach <id>`, the
  way an unattached tmux session already gets a new tab. This is new.
- **No terminal**: worked out before the click; the tile shows "no terminal", greyed, in place
  of the jump. A failed jump leaves its reason on the tile until the next poll. The page never
  opens a second copy of a running session.

## 9. Codex

*Tickets: "Which movement and stuck signals can Codex sessions give?", "How do Codex runs
appear on the overview?"*

- **`codex exec` runs** (1,563 of 1,808 rollouts here; median 1 minute, up to 6 at once):
  movement inside the tile of the Claude session that started them, "waiting on: codex review,
  2 min". No tile of their own. A run whose starter cannot be found gets an ordinary tile
  marked `exec`, placed by its launch folder.
- **Interactive Codex sessions** (7 in total, the last in August) use what the rollout gives:
  - movement: every record's `timestamp`;
  - busy and idle: `task_started` against `task_complete` or `turn_aborted`;
  - Limit: `task_complete` with `error.codex_error_info == "usage_limit_exceeded"`;
  - Error: the other `codex_error_info` values;
  - Needs you, **inferred**: an `exec_command` with `sandbox_permissions: "require_escalated"`
    and no output yet. Hung rules this out first, or a pending approval reads as Hung.
  - no working-on `did`: they start at `title`.
- **No Codex hooks for now.** Codex 0.147.0 has `stop` and `permissionRequest` hooks that would
  give a clean Needs you and a session line; revisit if interactive Codex use returns.
- **A Codex usage limit** is the page-wide banner (section 3).

## Configuration

New or changed keys in `config.json`, beside the existing ones:

| key | what | default |
|---|---|---|
| `assign` | a session's, track's or repository's project, keyed by track or repository (today: by `provider:id` only) | `{}` |
| `names` | project display names, keyed by track or repository | `{}` |
| `lines` | the person's own context line per project, beside its name | `{}` |
| `hung_after_minutes` | busy and not moving this long is Hung | 10 |
| `finished_after_minutes` | idle this long, with nothing pending, is Finished | 120 |

Today's `stuck_after_minutes` and `waiting_after_seconds` keep driving the flags the chime reads.

## Not decided here

Things the map did not settle, for the person to decide before or during the build:

- **Today's project pinning and drag order** (`pinned` in `config.json`) against "tracks
  first, No project last". The overview map never discussed it.
- **The key for the person's own context line.** Today `lines` holds a session's own text,
  keyed by `provider:id`; the project line needs its own key. `lines` in the table above is a
  placeholder name.
